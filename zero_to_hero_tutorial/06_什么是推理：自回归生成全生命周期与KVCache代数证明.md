# 第 6 篇：什么是推理？自回归生成全生命周期与 KV Cache 代数证明

> **阅读前须知**：许多人以为大模型“训练”和“推理”是一回事，只是输入不同而已。本篇我们将彻底厘清大模型推理（Inference）的物理本质，推导为什么模型只能逐字生成，以及为什么一个小小的 KV Cache 会成为大模型显存爆炸的万恶之源与工程关键。

---

## 🌓 一、训练（Training）vs 推理（Inference）的物理鸿沟

在讨论推理之前，我们必须先对比两者在底层运行模式上的根本差异：

| 对比维度 | 训练阶段 (Training) | 推理阶段 (Inference) |
| :--- | :--- | :--- |
| **已知信息** | **全部已知**（整篇文章的所有字都摆在眼前） | **完全未知**（只知道用户的 Prompt，答复一无所知） |
| **参数权重** | **频繁变动**（通过反向传播不断更新梯度） | **完全冻结**（只读参数，绝不更改） |
| **计算模式** | **全序列完全并行**（所有 Token 一瞬间同时算完） | **自回归逐字串行**（像挤牙膏一样一个词一个词蹦） |
| **显存杀手** | **激活值与优化器状态**（Adam 动量、权重梯度） | **模型权重与 KV Cache**（历史上下文缓存） |

### 训练时的“上帝视角”（Teacher Forcing）
训练时，我们给模型一段完整的文字：“人工智能彻底改变了世界”。
因为整句话都在显卡里，模型可以在**一次前向计算中，同时预测所有位置的下一个词**：
- 位置 1 的特征去预测“智能”；
- 位置 2 的特征去预测“彻底”；
- 位置 3 的特征去预测“改变”……
成千上万个词的预测误差在这一瞬间同时算出，然后梯度反向传播一次性更新全部参数。这就是为什么训练高度并行。

### 推理时的“摸黑前行”（自回归 Autoregressive Loop）
推理时，用户发来一个问题：“北京的特产是什么？”
模型此时根本不知道后续几百个字是什么，它只能像盲人摸象一样，玩一个**接龙游戏**：

```
Step 1: ["北京", "的", "特产", "是", "什么", "？"] ──► 模型前向运算 ──► 输出: "北京"
Step 2: ["北京", "的", "特产", "是", "什么", "？", "北京"] ──► 模型前向运算 ──► 输出: "烤鸭"
Step 3: ["北京", "的", "特产", "是", "什么", "？", "北京", "烤鸭"] ──► 模型前向运算 ──► 输出: "。"
```
**上一步自己吐出来的词，拼入原句作为下一步的输入，周而复始，直到吐出结束标记 `<eos>` 为止。这就是大模型自回归推理的全部物理本质！**

## ⚡ 二、推理的两大完全不同阶段：Prefill 与 Decode

在大模型推理系统（如 vLLM、TensorRT-LLM）中，你会每天听到两个术语：**Prefill（预填充）** 与 **Decode（解码）**。它们两者的硬件瓶颈截然相反！

```
用户输入 Prompt: "请用中文写一篇关于人工智能的千字论文..." (共 1000 字)
   │
   ▼ 【阶段 1: Prefill 阶段 (首字计算)】
   - 一次性把这 1000 个字并行输入给模型
   - 进行超大规模的矩阵相乘 [1000, 4096] x [4096, 4096]
   - 特征: GPU 的成千上万个计算核心全负荷拉满运转 (算力受限 Compute-Bound)
   - 核心考核指标: TTFT (Time To First Token，首字延迟，用户等多长时间看到第一个字)
   │
   ▼ 【阶段 2: Decode 阶段 (增量生成)】
   - 此时开始逐字输出，每次输入仅仅只有 1 个 Token！
   - 进行极小规模的矩阵-向量乘法 [1, 4096] x [4096, 4096]
   - 特征: 计算量极其微小，但为了这 1 个字，必须把整张显卡里几十 GB 的模型参数全部搬运一遍！
   - 算力严重闲置，显存带宽跑满 (访存受限 Memory-Bound)
   - 核心考核指标: TPOT (Time Per Output Token，单字生成耗时，打字机流式输出的流畅度)
```

## 🔍 三、KV Cache 的代数展开与冗余消除证明

现在我们进入推理系统中最核心的概念：**KV Cache**。

### 1. 朴素自回归计算中的重复劳动（无 KV Cache）
假设当前已经生成到了第 $t$ 个词，序列为 $[x_1, x_2, \dots, x_{t-1}, x_t]$。
我们要预测第 $t+1$ 个词。

根据 Transformer 注意力机制：
1. 计算整个序列的 Query、Key、Value：
   $$ Q_{1:t} = [x_1 W_q; x_2 W_q; \dots; x_t W_q] $$
   $$ K_{1:t} = [x_1 W_k; x_2 W_k; \dots; x_t W_k] $$
   $$ V_{1:t} = [x_1 W_v; x_2 W_v; \dots; x_t W_v] $$
2. 预测下一个词时，我们**只关心最后一个位置的 Query**：$q_t = x_t W_q$。
3. 最后一个位置的注意力加权计算为：
   $$ \text{Output}_t = \text{softmax}\left(\frac{q_t K_{1:t}^T}{\sqrt{d_k}}\right) V_{1:t} $$

#### 仔细看这里的 $K_{1:t}$ 和 $V_{1:t}$：
$$ K_{1:t} = [ \underbrace{x_1 W_k, x_2 W_k, \dots, x_{t-1} W_k}_{\text{历史前 } t-1 \text{ 个词的 Key}}, \quad x_t W_k ] $$
$$ V_{1:t} = [ \underbrace{x_1 W_v, x_2 W_v, \dots, x_{t-1} W_v}_{\text{历史前 } t-1 \text{ 个词的 Value}}, \quad x_t W_v ] $$

**发现了什么惊人的事实？**
- 权重矩阵 $W_k$ 和 $W_v$ 是固定冻结的；
- 历史上的词 $x_1, x_2, \dots, x_{t-1}$ 是已经说出来的话，绝不会再改变！
- 这意味着：**前面 $t-1$ 个词的 Key 和 Value 向量，在第 $t-1$ 步时就已经原模原样算过一次了！**
- 如果不保存它们，每生成一个新词，都要把前面所有历史词重新投影一遍。当文本长达 4000 字时，第 4001 步要把前 4000 个词的投影全量重算一遍！总计算量呈二次方 $O(T^2)$ 暴增，生成速度越来越慢！

---

### 2. KV Cache 的工程解法：以显存换算力
既然历史的 Key 和 Value 永远不会变，那我们**在第一次算出它们时，就直接保存在显存的缓存池中（KV Cache）**！

```
【第 t 步推理】：
输入: 只有最新生成的第 t 个词 x_t (单个向量 [1, d_model])
计算: 仅计算单向量的投影:
      q_t = x_t · W_q
      k_t = x_t · W_k
      v_t = x_t · W_v

更新缓存:
      K_all = [ K_cache,  k_t ]
      V_all = [ V_cache,  v_t ]

注意力打分:
      单向量 q_t 与 整个长矩阵 K_all 相乘 ──► 得到 [1, t] 的权重 ──► 加权 V_all 得到输出！
```

### 复杂度代数对比：
- **无 KV Cache**：每次前向需要做整个矩阵的投影 $O(t \cdot d_{\text{model}}^2)$，总共生成 $T$ 步需要累计 $O(T^2 \cdot d_{\text{model}}^2)$ 次计算。
- **有 KV Cache**：每次前向只需做单个向量的投影 $O(1 \cdot d_{\text{model}}^2)$，总计算量降为 $O(T \cdot d_{\text{model}}^2)$！
**投影与 FFN 这类"逐 token"矩阵乘法的总计算量少了一个因子 $T$（而不是常数倍）。**

> ⚠️ **严谨补充（容易被忽略）**：KV Cache 消除的是"对历史 token 重复做投影 / FFN"的冗余，**并没有消除注意力本身的二次方**：
> 第 $t$ 步里，新的 $q_t$ 仍然要和缓存中全部 $t$ 个 $k$ 做点积、再对 $t$ 个 $v$ 加权，代价是 $O(t \cdot d)$。累加 $T$ 步后注意力部分仍是 $O(T^2 d)$。
> 所以"有 Cache 后每步耗时恒定"只在 $t \cdot d \ll d_{\text{model}}^2$（上下文不长）时近似成立；上下文变长后，每一步都要从显存**读一遍整个 KV Cache**，这正是长上下文 Decode 变慢、以及 FlashDecoding / GQA / MLA / KV 量化出现的原因（见第 8、9、12 篇）。

## 💣 四、KV Cache 的代价：显存爆炸与 PagedAttention 的诞生

天下没有免费的午餐。KV Cache 用空间换取了时间，但带来了一个极度致命的副作用：**显存空间被疯狂吞噬！**

### 1. KV Cache 显存占用精确公式推导
对于一个大模型：
- 层数 $L$（每一层 Transformer 都有自己独立的 $K$ 和 $V$）
- 隐藏层维度 $H$
- 上下文总长度 $S$（输入的 Prompt 词数 + 已生成的词数）
- 并发请求数 $B$（Batch Size，同时服务的用户数）
- 浮点精度字节数 $b$（FP16/BF16 每个数字占 2 字节）

每个词需要存储一个 Key 向量（$H$ 个数字）和一个 Value 向量（$H$ 个数字），跨越全部 $L$ 层：
$$ \text{每个 Token 的 KV 显存} = 2 \times L \times H \times b \quad \text{(字节)} $$
如果同时服务 $B$ 个用户，平均每个请求长 $S$ 个词：
$$ \text{总 KV Cache 显存} = B \times S \times 2 \times L \times H \times b $$

#### 实例计算（一个 80 层、隐藏维度 8192、采用原始 MHA 的 70B 级模型）：
> 注：真实的 Llama-2-70B 已经使用了 GQA（64 个 Q 头、8 个 KV 头），下面的数字是"假如它仍用原始 MHA"的反事实计算——正是这个数字吓人，才逼出了 GQA。LLaMA-1-65B（80 层、8192 维、MHA）的量级与之相同。
- $L = 80$, $H = 8192$, $b = 2$（FP16）
- 单个 Token 的 KV Cache 显存：
  $$ 2 \times 80 \times 8192 \times 2 = 2,621,440 \text{ 字节} \approx 2.5 \text{ MB / token} $$
- 如果有 16 个用户并发（$B=16$），每个人对话长度为 4096 字（$S=4096$）：
  $$ 16 \times 4096 \times 2.5 \text{ MB} \approx 163,840 \text{ MB} = \mathbf{160 \text{ GB 显存}}！ $$

看到了吗？光是保存这一批对话的 KV Cache，就需要整整 **160 GB** 显存，这比 70B 模型本身的权重（140 GB）还要大！
而换成 GQA-8（Llama-2/3-70B 的真实配置）后，每 token 只需 $2 \times 80 \times (8 \times 128) \times 2 = 327{,}680$ 字节 $\approx 320$ KB，同样场景只要 **20 GB**——这就是 GQA 的价值。

### 2. 现代模型的架构救赎：GQA 与 PagedAttention
为了解决这个显存无底洞，学术界与工业界爆发了两场革命：
1. **模型结构革命：GQA（分组查询注意力）**
   - 既然存储全部 64 个头太费显存，那就让 8 个 Query 头共享 1 组 Key/Value 头（KV 头数压缩为 1/8）。
   - 现代 Llama-3、Qwen2.5 广泛采用 GQA，将 KV Cache 显存直接缩减为原来的 **1/4 到 1/8**！
2. **显存管理革命：PagedAttention（vLLM 破圈之作）**
   - 传统框架必须为每个请求提前申请连续的显存块（例如预留 4096 个词的空间），但大部分请求只聊了 100 句就退出了，导致 80% 的显存被预留却闲置浪费。
   - vLLM 借鉴了操作系统的虚拟分页技术，将 KV Cache 切成 16 个 token 一块的物理页，按需分配，零碎片浪费，让服务器并发能力暴增数倍！

## 🎯 总结与下一章预告

在本篇中，我们彻底理清了大模型推理的微观全貌：
1. **推理与训练的区别**：推理是权重冻结的自回归单向接龙；
2. **Prefill vs Decode**：Prefill 是首字并行算力受限（Compute-Bound），Decode 是逐字生成访存受限（Memory-Bound）；
3. **KV Cache 代数展开**：证明了历史 Key 和 Value 的不变性，通过缓存将计算复杂度从二次方降为线性；
4. **显存挑战**：KV Cache 随并发与长度线性膨胀，催生了 GQA 与 PagedAttention。
